# Talia Desktop

Talia Desktop is [Liana](https://github.com/wizardsardine/liana) by Wizardsardine with the Talia
design: name, logo, colours and glass finish, fonts, icons and the Talia vault graph. How it works is
Liana's: same features, same signing devices, same wallet files and folder, same engine (`lianad`).
Liana is BSD 3-Clause licensed; its copyright notice is kept in `LICENCE`, next to ours.

Kept on purpose: "Liana Connect" (Wizardsardine's own online service), "Liana descriptor"
(the file format), the "Liana daemon" (the engine), the `Liana-<checksum>` wallet ids, and the
data folder (`~/Library/Application Support/Liana`, `%APPDATA%\Liana`, `~/.liana`), so a client
who already uses Liana sees their wallets straight away.

The logo files are generated by `make_assets.py` from the Talia app icon and the brand font
(Bricolage Grotesque); the UI strings by `rebrand_i18n.py` (both in `contrib/talia/tools/`).

## Taking a new Liana release

1. `git fetch upstream --tags` and merge the new tag (for example `v17.0`) into this branch.
2. Re-run the text step on the new catalogs: `python3 -I contrib/talia/tools/rebrand_i18n.py liana-i18n/i18n`
   (it refuses to finish if one of the listed sentences moved, so nothing is missed silently),
   then `cargo run -p liana-i18n-toolbox -- sync` and `-- sync --verify` so the catalogs keep Liana's layout.
3. `grep -n '"Liana' liana-gui/src -r` for any new sentence naming the app.
4. Build, open, check the start screen, a wallet, Settings > About.
5. Sign, notarise, publish.

## The install window

`contrib/talia/make-dmg.sh <Talia Desktop.app> <out.dmg>` packs the signed app into the
download: the app on the left, an Applications shortcut on the right, and the drag-across
background (`contrib/talia/macos/dmg/`, design "B2" picked 2026-11-14: cream, a dark green
arrow, "Drag to Applications"; light on purpose, because Finder writes the names in dark
type on a picture background even in dark mode). It needs a Python with dmgbuild 1.x
(`pip install 'dmgbuild<2'`: 2.0 dropped the UDRW format the script writes first;
`PYTHON=...`). macOS 26 ignores the background link dmgbuild writes, so the script has
macOS itself make it (`background_bookmark.py`).

## Releasing

1. Mac: build for Apple and Intel Macs (`UNIVERSAL=1 build-macos-app.sh <dir>`), then
   `release-macos.sh "<app>" talia-desktop-mac.dmg`
   on the Mac that holds the team's "Developer ID Application" certificate and the
   `talia-notary` notarytool profile (both backed up in the company password manager).
   It signs, notarises and staples the app and the .dmg. Keep the Mac unlocked while it
   runs: a locked screen hides the signing key and the notarytool profile. Apple's first
   checks for a new team can take many hours; if the wait runs out, the script keeps the
   signed app (`talia-desktop-mac-signed.app`). Once `xcrun stapler staple` on it works,
   run the script again on that app: it skips straight to the .dmg.
2. Windows: GitHub > Actions > "Talia Desktop for Windows" > Run workflow; rename the
   artifact to `talia-desktop-windows.exe`. Not code-signed (decided 2026-11-14).
3. Publish a GitHub release with `talia-desktop-mac.dmg`, `talia-desktop-windows.exe` and
   `SHA256SUMS.txt`. The website's download buttons follow `releases/latest` under these
   file names, so they need no change.

## Building on a Mac

```
contrib/talia/build-macos-app.sh <output dir>             # this Mac's chip
UNIVERSAL=1 contrib/talia/build-macos-app.sh <output dir> # Apple silicon + Intel
```
